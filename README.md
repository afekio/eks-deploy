# 🚀 Infrastructure Provisioning App

A streamlined web application designed for generating Terraform provisioning files. It allows users to quickly create configuration files for AWS and Proxmox, featuring built-in user management and secure, efficient access to generated files.

---

## 📖 Overview
The application provides an intuitive web interface where users can register, log in, and generate the necessary infrastructure files. Each user has a personal dashboard to view, manage, and download their previously generated files.

## 🏗️ Architecture
The application is built using a modern microservices architecture:
* **Frontend:** A React-based user interface served by Nginx.
* **Backend:** A Python service that handles the core provisioning logic, data validation, and internal logging.
* **Auth:** Manages user authentication and communicates directly with the database, routing user-specific data from the backend.
* **Database:** PostgreSQL serves as the primary database for the application.

## ☁️ Cloud Infrastructure
The backend infrastructure is hosted entirely on AWS and utilizes the following services:
* **Amazon EKS:** Manages the Kubernetes cluster running on EC2 `t4g` instances (Note: The application runs exclusively on ARM architecture).
* **Amazon S3:** Stores the provisioning files generated by the backend securely.
* **Amazon SNS:** Handles email notifications via a dedicated topic.
* **IAM & IRSA:** Manages secure, fine-grained access control between EKS pods and other AWS services.
* **Amazon EFS:** Provides persistent storage, configured with a Kubernetes StorageClass.
* **Amazon VPC:** A custom network layout designed specifically for the application's routing and security requirements.

## ⚙️ Deployment Flow
The entire deployment process is fully automated using **Ansible** and **Terraform**. 
1. Ansible triggers Terraform to provision the underlying AWS infrastructure. 
2. Once the infrastructure is ready, Ansible takes Terraform's outputs and injects them directly into the Kubernetes deployment manifests.

**The Kubernetes cluster runs the following workloads:**
* **Frontend:** Runs at least 2 pods (distributed across nodes) for High Availability (HA).
* **Backend:** Runs at least 2 pods (distributed across nodes).
* **Auth:** Runs at least 2 pods (distributed across nodes).
* **PostgreSQL:** Managed via the CloudNativePG (CNPG) operator, running 2 pods (1 primary, 1 replica) across different nodes to ensure database failover and redundancy.
* **Ingress:** Uses `nginx-ingress-controller` exposed as an AWS Network Load Balancer (NLB). It routes external traffic to the frontend and intelligently directs API calls to the backend and auth services.

🔒 Managing Secrets with Ansible Vault
Navigate to the ansible directory:

### Encrypting Secrets
Create a file named .vault_pass.txt and enter a strong password inside it. Keep this file secure and never share it.
```bash
cd ansible
echo "your_strong_password" > .vault_pass.txt
```

Open the provided vault-plaintext.example.yml file and update the environment passwords with your own values.

Encrypt the file and save it to the correct location by running the following command:

```bash
ansible-vault encrypt vault-plaintext.example.yml --output group_vars/all/vault.yml
```
You can verify the encryption was successful and view your secrets by running:

```bash
ansible-vault view group_vars/all/vault.yml
```
### 🛠️ Configuring Variables
### Configure the main deployment variables by editing the following file:

```yaml
group_vars/all/main.yml
```
#### 📝 Note: If you are unsure about these settings, leave the defaults. The application will deploy successfully without modifications, except for one required field.

You must update the `sns_subscription_emails` variable with the email addresses that should receive system notifications.

▶️ Running the Deployment
Ensure your terminal is in the Ansible project directory:

Bash
cd deploy-eks-project/ansible
Execute the deployment playbook:

Bash
ansible-playbook site.yml
The deployment steps will output to your terminal. The Terraform provisioning phase takes some time, so feel free to grab a coffee ☕.

Once the process completes, the terminal will output a URL. This is the Load Balancer DNS name you will use to access the application in your browser.

📧 Crucial Post-Deployment Step
Check the inbox of the email address you configured earlier. You must click the confirmation link in the AWS SNS subscription email. If you do not confirm this subscription, you will not receive application alerts.

The application sends alerts for the following events:

New user registration.

Failed login attempts.

File views or downloads from a user's personal dashboard.

🚨 Destroying the Infrastructure
To avoid incurring unnecessary AWS charges, you can completely tear down the environment when you are done testing.

From the ansible directory, run:

Bash
ansible-playbook destroy.yml -e confirm=yes
🛑 DANGER: This is a destructive action. It will permanently delete the entire infrastructure, including the database, the S3 buckets, and all files you have generated.
